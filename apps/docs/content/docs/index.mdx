Run your first automatic check after an agent edits a file. You'll need Git
and a signed-in Codex, Claude Code, or GitHub Copilot CLI.

## 1. Install the CLI

Choose an install method. Each sets `LATCH_DIR` to the directory containing
the plugin catalogs. Run the remaining steps in the same terminal.

<Tabs items={['Cargo', 'npm tarballs', 'Standalone archive']}>

<Tab value="Cargo">

Run these commands from the root of the Latch checkout in a macOS or Linux
terminal with Rust and Cargo installed.

```sh
export LATCH_DIR="$(pwd)"
cargo install --locked --path crates/latch
export PATH="${CARGO_HOME:-$HOME/.cargo}/bin:$PATH"
latch --version
```

</Tab>

<Tab value="npm tarballs">

Use Node.js 18 or newer. From the directory containing the wrapper tarball
and the binary tarball for your platform, run the following. This example
uses Linux x64. For ARM64 Linux or Apple Silicon, use the matching
`linux-arm64` or `darwin-arm64` tarball.

```sh
npm install -g ./barakchamo-latch-0.1.0.tgz ./barakchamo-latch-linux-x64-0.1.0.tgz
export LATCH_DIR="$(npm root -g)/@barakchamo/latch"
export PATH="$(npm prefix -g)/bin:$PATH"
latch --version
```

<Callout title="Preview packages">
The npm registry package is pending publication. Use the tarballs from a
[local build](https://github.com/BarakChamo/latch/blob/main/docs/releasing.md)
or a successful [Package release run](https://github.com/BarakChamo/latch/actions/workflows/package-release.yml).
</Callout>

</Tab>

<Tab value="Standalone archive">

Extract the archive for your platform. This example uses Linux x64.

```sh
tar -xzf latch-0.1.0-x86_64-unknown-linux-gnu.tar.gz
export LATCH_DIR="$PWD/latch-0.1.0-x86_64-unknown-linux-gnu"
export PATH="$LATCH_DIR/bin:$PATH"
latch --version
```

The extracted directory includes the native CLI and all three plugin catalogs.
See the [release guide](https://github.com/BarakChamo/latch/blob/main/docs/releasing.md)
for the archive names and checksums.

</Tab>

</Tabs>

## 2. Enable your harness plugin

Run the commands for your harness.

<Tabs items={['Codex', 'Claude Code', 'GitHub Copilot CLI']}>

<Tab value="Codex">

```sh
codex plugin marketplace add "$LATCH_DIR"
codex plugin add latch@latch-local
```

</Tab>

<Tab value="Claude Code">

```sh
claude plugin marketplace add "$LATCH_DIR"
claude plugin install latch@latch-marketplace
```

</Tab>

<Tab value="GitHub Copilot CLI">

```sh
copilot plugin marketplace add "$LATCH_DIR"
copilot plugin install latch@latch-marketplace
```

</Tab>

</Tabs>

## 3. Run your first check

Create a disposable Git project. Its check reports changes to `demo.txt`.

```sh
cd "$(mktemp -d)"
git init -q
printf 'ready\n' > demo.txt
cat > latch.json <<'JSON'
{
  "hooks": {
    "after_edit": {
      "commands": [["git", "diff", "--exit-code", "HEAD", "--", "demo.txt"]]
    }
  }
}
JSON
git add demo.txt latch.json
git -c user.name="Latch Demo" -c user.email="latch@example.test" \
  -c commit.gpgsign=false commit -qm "Add Latch demo"
latch explain after_edit
latch run after_edit && printf 'Check passed\n'
```

`latch explain` shows the resolved Git command. The command passes on a
clean worktree, so Latch stays quiet and the shell prints `Check passed`.

Start a **new harness session** from this directory using `codex`, `claude`,
or `copilot`. If the harness asks you to trust the demo directory, review
and accept it. In Codex, open `/hooks` and review and trust the Latch hooks.
Then give the agent this prompt.

> Use your native edit tool to replace `ready` in `demo.txt` with
> `changed`. Leave the change in place and finish the turn.

The automatic edit hook reports **Latch checks failed** and shows a diff
from `ready` to `changed`. This is the expected result. You can restore
`demo.txt` with `git restore -- demo.txt`.

In your own project, add a [package script](/docs/project-scripts) or
[configure a command](/docs/configuration). See
[hooks and feedback](/docs/hooks) for when reports appear.
