Latch gives your coding agent a feedback loop using commands your project
already runs. Install a plugin to run checks automatically, or use the
standalone CLI from your terminal or CI.

- [Run your first check](/docs/quickstart) with an existing project command.
- [See what your harness supports](#compatibility) for local or hosted sessions.
- [Try a complete example](#examples) for script discovery or file filters.

## When to use Latch

Use Latch when you want checks to happen consistently across agent sessions.
An edit can trigger a quick lint check, and a changed turn can trigger the
tests or build that need the complete set of changes.

## How it works

| Event | Use it for |
| --- | --- |
| `after_edit` | Fast checks after a supported native file edit, such as lint or formatting. |
| `turn_end` | Checks that should run once after a changed turn, including turns with shell edits. |

- **Run only what’s relevant.** Git comparison skips unchanged turns and no-op edits by default. Filter by path or extension to narrow it further. [Hook lifecycle](/docs/hooks)
- **Keep feedback focused.** Passing checks are quiet by default. Latch can shorten long failures and link to the original log. [Output modes](/docs/configuration#failure-output-modes)
- **Use your existing commands.** Set them in `latch.json` for any language, or skip the file when Latch discovers the scripts you want. [Set up checks](/docs/quickstart#run-your-first-check)

## Examples

- **TypeScript with npm.** Check formatting after edits, then run TypeScript and Vitest at turn end. [Walkthrough](/docs/project-scripts#typescript-example)
- **Python with uv.** Run Ruff after edits and unit tests at turn end, with shared output settings. [Walkthrough](/docs/project-scripts#python-example)
- **Filter several checks on one event.** Run a general check on every edit and add Markdown and TypeScript checks only when their files change. [Configuration examples](/docs/configuration#examples)

## Compatibility

The default delivery of failures depends on the agent and event. For a supported agent, opt in to `"turn_end_feedback": "continue_once"` to give it one chance to respond to a failed turn-end check automatically, without another message from you or an automatic recheck. [Local feedback compatibility matrix](/docs/hooks#where-reports-appear) · [Opt-in turn-end feedback](/docs/hooks#act-on-a-turn-end-failure) · [Cloud sessions](/docs/cloud)
