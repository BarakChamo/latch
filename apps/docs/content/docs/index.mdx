Latch automatically runs your project’s linters, tests, and other checks while your coding agent works, so it can see failures without being asked to run the checks.

[How it works](#how-it-works) · [Install a plugin](#install-a-plugin) · [Run your first check](#run-your-first-check) · [Standalone CLI](#install-the-standalone-cli) · [Docs](#docs)

## How it works

Plugins map their agents’ native hooks to two shared Latch events. Available events vary by agent, but your check commands stay in the project and work with any integration.

| Event | When checks run |
| --- | --- |
| `after_edit` | After a supported file-edit tool changes the worktree. Use it for fast checks such as linting. |
| `turn_end` | When the agent finishes a turn that changed the worktree. This catches shell edits and works well for tests. |

By default, Latch compares Git-visible files before and after the edit or turn, so an already-dirty file only counts if it changes again. Passing checks are quiet by default. Most agents get edit failures in the same turn. Turn-end failures may appear in the session or reach the agent on the next prompt, depending on the integration. The turn finishes normally. See [hook timing and feedback by agent](/docs/hooks).

## Install a plugin

The marketplace plugins below bundle the CLI for macOS and glibc Linux on ARM64 and x64.

### Codex

```sh
codex plugin marketplace add BarakChamo/latch --ref codex/marketplace
codex plugin add latch@latch-tools
```

In a new Codex session in your project, review and approve the Latch hooks in `/hooks`.

### Claude Code

```sh
claude plugin marketplace add 'BarakChamo/latch#codex/marketplace'
claude plugin install latch@latch-tools
```

### GitHub Copilot CLI

```sh
copilot plugin marketplace add 'https://github.com/BarakChamo/latch.git#codex/marketplace'
copilot plugin install latch@latch-tools
```

Start a new session in your project after installing. For OpenCode, Pi, and other agents, see the [integration guides](/docs/plugins).

## Run your first check

**`latch.json` is optional.** Latch can discover checks from `package.json` or `pyproject.toml`.

For example, if your npm project already has a `lint` script, add `hook:afteredit` to the existing `scripts` object in `package.json`:

```json
{
  "scripts": {
    "hook:afteredit": "npm run lint"
  }
}
```

Ask the agent to change a file with its edit tool, and Latch runs the script. Use `hook:turnend` for a check at the end of the turn. For Python projects using uv, see the [Python entry-point example](https://github.com/BarakChamo/latch/tree/main/examples/python).

### Configure checks

To run commands directly, set defaults, or filter by changed files, add `latch.json` in the directory where the agent runs. For example, run Ruff from an existing uv project:

```json
{
  "hooks": {
    "after_edit": {
      "commands": [["uv", "run", "ruff", "check", "."]]
    }
  }
}
```

Explicit commands and discovered scripts can be used together. See the [configuration reference](/docs/configuration) for ordering, defaults, and filters.

## Install the standalone CLI

For terminal or CI use, download and extract your platform’s archive from [GitHub Releases](https://github.com/BarakChamo/latch/releases/latest) and follow the [CLI installation guide](/docs/cli#install-the-cli).

From your project, run `latch run after_edit` or `latch run turn_end` to execute that event’s checks immediately. This works with either package scripts or `latch.json`. Use `latch explain after_edit` to see what Latch resolved.
