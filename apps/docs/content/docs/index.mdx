Your agent edits three files and says it’s done. You run the type checker
and discover an error in the first file. Now you have to copy the output
back into the chat and explain what happened.

**Latch runs your project’s checks while the agent is still working.**
It gives the agent the failure output from the tools you already use,
so you can spend less time running checks and relaying errors.

## What this looks like

Say your project already has a type-check command. Set Latch to run it
after an edit. When an agent changes a file, Latch runs the check and puts
any error alongside the edit result, where the agent can use it. A passing
check stays quiet by default.

You can run a fast check after edits and save a longer test suite for the
end of the turn. Latch skips unchanged work by default. Your project owns
the commands in its [package scripts](/docs/project-scripts) or
[`latch.json`](/docs/configuration), so you can use the same checks when
you switch agents.

## Get started

[Install the bundled plugin](/docs/quickstart) and try a check in a small
example project. The bundle includes the Latch executable.

See [Harness plugins](/docs/plugins) for supported hosts and how to run
checks from chat.
