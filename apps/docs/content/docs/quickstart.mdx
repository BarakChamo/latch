Start in a Git project with a check you already run, such as a linter. The plugin handles automatic checks, and the standalone CLI is available for terminal and CI runs.

## Install a plugin

Choose your agent. The marketplace plugins support macOS and glibc Linux on ARM64 and x64.

<Tabs items={['Codex', 'Claude Code', 'GitHub Copilot CLI', 'Pi', 'OpenCode']}>

<Tab value="Codex">

```sh
codex plugin marketplace add BarakChamo/latch --ref codex/marketplace
codex plugin add latch@latch-tools
```

Open a new Codex session in your project, then review and approve the Latch hooks in `/hooks`.

</Tab>

<Tab value="Claude Code">

```sh
claude plugin marketplace add 'BarakChamo/latch#codex/marketplace'
claude plugin install latch@latch-tools
```

</Tab>

<Tab value="GitHub Copilot CLI">

```sh
copilot plugin marketplace add 'https://github.com/BarakChamo/latch.git#codex/marketplace'
copilot plugin install latch@latch-tools
```

</Tab>

<Tab value="Pi">

Use Pi 1.5.2 or later with MCP enabled.

```sh
pi install git:github.com/BarakChamo/latch
```

</Tab>

<Tab value="OpenCode">

For OpenCode 2.3.2 or later:

```sh
opencode plugin add 'github:BarakChamo/latch#main::path:plugins'
```

The plugin downloads the Latch binary from GitHub on first use and caches it. [Other integrations](/docs/plugins#additional-local-integrations)

## Run your first check

Pick a command that already works in your project. **Use `latch.json` to run commands in any language.** You can skip the file if Latch can discover a named script in your `package.json` or a console entry point in your packaged uv project.

### Run any project command

Create `latch.json` in the directory where you run your checks. If you already use `make lint`, configure it like this.

```json title="latch.json"
{
  "hooks": {
    "after_edit": {
      "commands": [["make", "lint"]]
    }
  }
}
```

Replace the example with your own command, such as `["go", "test", "./..."]`,
`["uv", "run", "ruff", "check", "."]`, or `["./scripts/check"]`. Put the
executable first and each argument in a separate string. Install your
project’s dependencies so the agent can run the command. Use `turn_end`
for checks you want to run once per changed turn.

You can create the file by hand or generate a starter with `latch config init`
from the [standalone CLI](/docs/cli#install-the-cli). [Configuration examples](/docs/configuration#examples)

### Use package scripts without latch.json

Latch discovers these names in the project directory. If your project
already defines one, start a session with the plugin enabled.

<Tabs items={['package.json', 'pyproject.toml with uv']}>

<Tab value="package.json">

For example, add `hook:afteredit` to the existing `scripts` object in an npm project that already has a `lint` script.

```json title="package.json"
{
  "scripts": {
    "hook:afteredit": "npm run lint"
  }
}
```

Use `hook:turnend` to run a script at the end of a changed turn. Latch supports npm, pnpm, Yarn, and Bun. [Package manager selection](/docs/project-scripts#javascript-and-typescript)

</Tab>

<Tab value="pyproject.toml with uv">

In a packaged uv project, add a console entry point under `[project.scripts]`. For example, the [runnable Python project](/docs/project-scripts#python-example) points to a function that runs Ruff and returns its exit status.

```toml title="pyproject.toml"
[project.scripts]
hook-afteredit = "latch_python_example.checks:after_edit"
```

Use `hook-turnend` for a turn-end check. For a regular command such as `uv run pytest`, use the `latch.json` recipe above. [Python entry-point setup](/docs/project-scripts#python-with-uv)

</Tab>

</Tabs>

### Try it in your agent

1. Start a fresh agent session in the project directory. For `after_edit`, ask the agent to make a real change using its native edit tool. For `turn_end`, let it finish a turn that changes a file.
2. Passing checks are silent. To see a report, try a change that makes your check fail, then restore the file. The [runnable examples](/docs/project-scripts#try-the-examples) show exactly what to change.
3. If no report appears, check [where your agent delivers it](/docs/hooks#where-reports-appear). With the standalone CLI, run `latch explain after_edit` or `latch explain turn_end` to see which command Latch found.

## Run the same check from a terminal

Install the [standalone CLI](/docs/cli#install-the-cli), then run these from your project directory.

```sh
latch explain after_edit
latch run after_edit
```

`explain` shows the resolved command and settings. `run` executes the check immediately, even when no files have changed. Use `latch run turn_end` in CI if your project defines turn-end checks.

Once the first check works, add [path or file-type filters](/docs/configuration#examples) or [give the agent one automatic response to a turn-end failure](/docs/hooks#act-on-a-turn-end-failure).
