---
title: Quickstart
description: Install Latch and run your first project check.
---

Run one automatic check in a disposable Git project. You’ll see what
Latch reports when an edit fails, then you can reuse the same setup
with your own formatter, linter, or test suite.

## 1. Install Latch from the release

With Node.js 18 or later, download these two files from
[GitHub Releases](https://github.com/BarakChamo/latch/releases/latest):

- `barakchamo-latch-0.1.0.tgz`
- The [platform tarball](/docs/cli#install-the-cli) for your machine

Open a terminal in the directory containing both files. This command
uses the Apple Silicon tarball. Substitute the second filename for your platform.

```sh
npm install --global --offline ./barakchamo-latch-0.1.0.tgz ./barakchamo-latch-darwin-arm64-0.1.0.tgz
latch --version
```

GitHub requires access to the Latch repository to download the files.
For a standalone executable or a Cargo build, use the
[CLI install guide](/docs/cli#install-the-cli).

## 2. Enable Latch in your agent

For Codex, use the CLI to add the installed package as a local plugin source:

```sh
codex plugin marketplace add "$(npm root -g)/@barakchamo/latch"
codex plugin add latch@latch-local
```

For Claude Code, Copilot CLI, OpenCode, Pi, or another supported agent,
follow its [setup instructions](/docs/plugins). OpenHands and Grok Build
register hooks from the Git project you create in the next step. For
Kimi Code, change the example event to `turn_end`.

## 3. Run your first check

Create a disposable Git project. Its check reports changes to `demo.txt`.

```sh
cd "$(mktemp -d)"
git init -q
printf 'ready\n' > demo.txt
cat > latch.json <<'JSON'
{
  "hooks": {
    "after_edit": {
      "commands": [["git", "diff", "--exit-code", "HEAD", "--", "demo.txt"]]
    }
  }
}
JSON
git add demo.txt latch.json
git -c user.name="Latch Demo" -c user.email="latch@example.test" \
  -c commit.gpgsign=false commit -qm "Add Latch demo"
```

Start your agent from the demo directory. For Codex, run `codex` there.
If prompted, review and
approve trust for the project first. In Codex, review and approve the
Latch hooks at the startup prompt. If the hook prompt doesn’t appear, open
`/hooks` to review and approve them. Send the agent this prompt.

> Use your native edit tool to replace `ready` in `demo.txt` with
> `changed`. Leave the change in place and finish the turn.

The report says **Latch checks failed** and shows a diff from `ready`
to `changed`. In OpenHands or Kimi Code, send another prompt to see the
report. If the report includes a `Saved log` path, open that file to see
the full output. [Feedback timing by harness](/docs/hooks#where-reports-appear) Restore the demo
with `git restore -- demo.txt`.

In your own project, add a [package script](/docs/project-scripts) or
[configure a command](/docs/configuration). See
[plugin reference](/docs/plugins) to run checks from chat.
