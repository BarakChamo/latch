title: Quickstart
description: Install Latch and run your first project check.
---

Try an automatic check in a disposable Git project. You’ll need Git and a
[supported coding agent](/docs/plugins).

## 1. Download Latch

Sign in to GitHub with an account that has access to the private Latch
repository, then download the bundle for your machine. The bundle includes
the CLI and plugins.

| Your machine | Download |
| --- | --- |
| Mac with Apple Silicon | [macOS ARM64](https://github.com/BarakChamo/latch/releases/download/preview-0.1.0/latch-0.1.0-aarch64-apple-darwin.tar.gz) |
| Mac with Intel | [macOS x64](https://github.com/BarakChamo/latch/releases/download/preview-0.1.0/latch-0.1.0-x86_64-apple-darwin.tar.gz) |
| Linux on Intel or AMD | [Linux x64](https://github.com/BarakChamo/latch/releases/download/preview-0.1.0/latch-0.1.0-x86_64-unknown-linux-gnu.tar.gz) |
| Linux on ARM64 | [Linux ARM64](https://github.com/BarakChamo/latch/releases/download/preview-0.1.0/latch-0.1.0-aarch64-unknown-linux-gnu.tar.gz) |

If you’re unsure, run `uname -m` in a terminal. Choose ARM64 for
`arm64` or `aarch64` and x64 for `x86_64`.

If GitHub shows 404, check that you accepted your repository invitation and
are signed in with the invited account. If you received an archive separately,
use that file. The [preview release](https://github.com/BarakChamo/latch/releases/tag/preview-0.1.0)
also has checksums and npm tarballs. For a source build, see
[other install methods](/docs/cli#install-the-cli).

## 2. Install the plugin

Extract the bundle and open a terminal in its folder. On an Apple Silicon
Mac, for example:

```sh
cd ~/Downloads
tar -xzf latch-0.1.0-aarch64-apple-darwin.tar.gz
cd latch-0.1.0-aarch64-apple-darwin
./bin/latch --version
```

Run the install command for your agent. Keep the extracted folder in place.

| Agent | Install | Sign in or choose a model if needed |
| --- | --- | --- |
| Codex | `./install codex` | `codex login` |
| Claude Code | `./install claude` | `claude auth login` or `/login` in Claude Code |
| GitHub Copilot CLI | `./install copilot` | `copilot login` |
| OpenCode | `./install opencode` | Run `/connect` in OpenCode, then choose a model with `/models`. |
| Pi | `./install pi` | Run `/login` in Pi, then choose a model with `/model`. |

Use an interactive terminal for sign-in and approval prompts. If the
terminal reports `TERM=dumb`, open a terminal app that supports interactive
sessions before continuing.

## 3. Run your first check

Create a disposable Git project. Its check reports changes to `demo.txt`.

```sh
cd "$(mktemp -d)"
git init -q
printf 'ready\n' > demo.txt
cat > latch.json <<'JSON'
{
  "hooks": {
    "after_edit": {
      "commands": [["git", "diff", "--exit-code", "HEAD", "--", "demo.txt"]]
    }
  }
}
JSON
git add demo.txt latch.json
git -c user.name="Latch Demo" -c user.email="latch@example.test" \
  -c commit.gpgsign=false commit -qm "Add Latch demo"
```

Start a new session from the demo directory. If prompted, review and
approve trust for the project first. In Codex, then review and approve the
Latch hooks at the startup prompt. If the hook prompt doesn’t appear, open
`/hooks` to review and approve them. Send the agent this prompt.

> Use your native edit tool to replace `ready` in `demo.txt` with
> `changed`. Leave the change in place and finish the turn.

The automatic edit hook reports **Latch checks failed** and shows a diff
from `ready` to `changed`. This is the expected result. If the report includes a
`Saved log` path, open that file to see the full output. Restore the demo
with `git restore -- demo.txt`.

In your own project, add a [package script](/docs/project-scripts) or
[configure a command](/docs/configuration). See
[plugin reference](/docs/plugins) to run checks from chat.
