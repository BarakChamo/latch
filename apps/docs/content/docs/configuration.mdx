Use `latch.json` to run commands in any language and customize automatic
checks. The file is optional when [package script discovery](/docs/project-scripts)
finds the checks you want.

| To change | Set |
| --- | --- |
| Which commands run and when | `hooks.after_edit` or `hooks.turn_end`. Checks run on changes by default. [Examples](#examples) |
| Which changes count | `paths` or `extensions` on an individual hook object. [Hook fields](#hook-fields) |
| What checks report | `on_success` defaults to `"silent"`, and `on_failure` defaults to `"collect"`. Set these in `defaults` or override them per hook. [Ordering and overrides](#ordering-and-overrides) |
| How much output to show | `failure_output` chooses an excerpt, compact diagnostics, the last few lines, or RTK. [Output modes](#failure-output-modes) |
| Whether the agent responds automatically | Top-level `turn_end_feedback` defaults to `"report"`. Opt in to `"continue_once"` on supported harnesses. [Turn-end feedback](/docs/hooks#act-on-a-turn-end-failure) |

## Create a config

Create `latch.json` in the directory where checks should run, or generate a
starter there with the [standalone CLI](/docs/cli#install-the-cli).

```sh
latch config init
```

The starter keeps package script discovery enabled. If `latch.json` already
exists, the command leaves it in place.

## Editor completion and validation

The starter points to the hosted schema. For offline editor completion,
copy [`latch.schema.json`](https://github.com/BarakChamo/latch/blob/main/latch.schema.json)
from the Latch repository, standalone archive, or npm wrapper into your
project next to `latch.json`. Add `"$schema": "./latch.schema.json"` as
a top-level property. Editors that support JSON Schema can then suggest
fields and flag invalid values. Latch validates configuration and compiles
path globs at runtime.

## Examples

Try the [runnable path and extension filter example](https://github.com/BarakChamo/latch/tree/main/examples/filters)
to see which checks run for different edits.

<Tabs items={['One check', 'Filter by file type', 'Defaults only']}>

<Tab value="One check">

```json title="latch.json"
{
  "hooks": {
    "turn_end": {
      "commands": [["cargo", "fmt", "--all", "--", "--check"]]
    }
  }
}
```

Run a Rust formatting check at turn end when the worktree changes.

</Tab>

<Tab value="Filter by file type">

```json title="latch.json"
{
  "hooks": {
    "after_edit": [
      { "commands": [["npm", "run", "lint"]] },
      { "extensions": ["md", "mdx"], "commands": [["npm", "run", "lint:md"]] },
      {
        "paths": ["src/**"],
        "extensions": ["ts", "tsx"],
        "commands": [["npm", "run", "typecheck"]]
      }
    ]
  }
}
```

A Markdown edit runs lint and Markdown lint. A TypeScript edit in `src/`
runs lint and type checking. An edit that changes both runs all three in order.
A JSON-only edit runs the general linter.

</Tab>

<Tab value="Defaults only">

```json title="latch.json"
{
  "defaults": {
    "on_success": "output",
    "on_failure": "stop"
  }
}
```

Use this with package scripts to show successful output and stop a command list at
its first failure.

</Tab>

</Tabs>

## Hook fields

<TypeTable type={{
  commands: { type: 'string | string[][]', required: true, description: 'One command as a string, or a list of commands as nested argument arrays.' },

  failure_output: { type: '"excerpt" | "compact" | "tail" | "rtk"', default: 'excerpt', description: 'Controls failed command output in hooks and the plugin tool. Compact selects diagnostics, tail shows the last lines, and rtk uses an external filter.' },
  tail_lines: { type: 'integer', default: '20', description: 'The maximum number of lines to show per stream in tail mode. Valid values range from 1 to 100.' },
  rtk_filter: { type: 'string', default: 'log', description: 'The RTK stdin filter to use in rtk mode, such as vitest, cargo-test, or tsc.' },
  paths: { type: 'string[]', description: 'Case-sensitive globs relative to the Git worktree. Use / as the separator and ** to match across directories.' },
  extensions: { type: 'string[]', description: 'Case-insensitive final filename suffixes, with an optional leading dot.' },

An object runs once if any changed file passes its filters. When both filters
are set, the same file must match at least one pattern and one suffix. Renames
can match either path. Empty filter lists are invalid.

## Command syntax

| Use | Example value for `commands` |
| --- | --- |
| One command as text (v0.1.5+) | `"bun run lint"` |
| Several commands in order | `[["make", "lint"], ["make", "test"]]` |

Latch splits strings with POSIX shell-style quotes and escapes. For example,
`"node check.js 'file with spaces.ts'"` passes the filename as one argument.
Latch launches the executable directly, so pipes, redirects, environment
variable references, and globs are literal arguments. To use shell features,
invoke a shell explicitly, for example `[["sh", "-c", "make lint && make test"]]`.
Use nested arrays to preserve exact arguments, including for a single
command such as `[["make", "lint"]]`. Flat arrays are invalid.
`commands: []` adds no explicit commands and leaves discovery enabled.

## Ordering and overrides

A hook object inherits each setting it omits. Matching hook objects run in the
order they appear. Discovered commands run together after explicit objects
and inherit the global defaults.

Set an event to `[]` to disable it, including discovery. Set `hooks` to
`{}` to disable both events.

Use `latch explain after_edit` or `latch explain turn_end` to see which
commands and settings Latch resolved.

## Failure output modes

| Mode | What the report shows |
| --- | --- |
| `"excerpt"` (default) | A bounded preview of stdout and stderr. |
| [`"compact"`](#compact-failure-output) | Selected diagnostics such as assertion messages and failure names. |
| [`"tail"`](#tail-failure-output) | The last `tail_lines` lines of each stream. |
| [`"rtk"`](#rtk-failure-output) | Output from a locally installed RTK filter, with compact output as a fallback. |

When a report shortens output, it includes a path to the saved log if
Latch could save it. Open the log directly, search it from chat, or use
the [CLI to replay the original streams](/docs/cli#retrieve-saved-output).
Direct `latch run` calls print the original streams.

### Compact failure output

```json title="latch.json"
{
  "defaults": { "failure_output": "compact" }
}
```

Compact mode keeps streams up to 1,200 bytes as-is. For each longer stream, it selects
diagnostics such as failure names and assertions, drops repeats, and
keeps a few lines from the end. Command failures and exit statuses
still appear in order. The renderer runs locally without a model call.

### Tail failure output

```json title="latch.json"
{
  "defaults": { "failure_output": "tail", "tail_lines": 12 }
}
```

Tail mode shows up to the last 12 lines each from stdout and stderr in this
example. Latch shortens unusually long lines from the left. When the preview
omits output, the report includes the saved log path. Override the mode or
line count on an individual hook.

### RTK failure output

Install [RTK](https://github.com/rtk-ai/rtk/blob/develop/INSTALL.md) separately
and make sure `rtk` is on your harness's `PATH`. For a Vitest project:

```json title="latch.json"
{
  "hooks": {
    "turn_end": {
      "failure_output": "rtk",
      "rtk_filter": "vitest",
      "commands": [["npm", "test"]]
    }
  }
}
```

Latch runs the check once and passes its captured output to
`rtk pipe --filter vitest`. The report uses the check's original exit
status and includes a path to the original stdout and stderr.
Latch adds a compact stderr preview when it detects a diagnostic the
filter omitted. If RTK
is missing, rejects the filter, returns an empty preview, or takes more
than two seconds, Latch shows the built-in compact preview instead.
The standalone CLI and plugin bundle use the same external lookup.
