## Commands

| Command | What it does |
| --- | --- |
| `latch explain after_edit` | Show the edit commands, filters, and resolved settings. |
| `latch explain turn_end` | Show the turn-end plan. `latch explain` is shorthand. |
| `latch run after_edit` | Run all edit checks immediately. |
| `latch run turn_end` | Run all turn-end checks immediately. `latch` is shorthand. |
| `run_turn_end` | Run turn-end checks through the plugin's MCP tool and return their report. |

Manual runs bypass change detection and file filters. CLI exit codes are
`0` for success, `1` for a check or configuration failure, and `2` for invalid usage.

## The hook is quiet

1. Run `latch explain` for the event from the project directory. Check
   `configured`, the command list, and any file filters.
2. Run the same event with `latch run`. Successful commands are silent by
   default. Append `&& echo passed` in a POSIX shell to confirm success.
3. Confirm your harness loaded the plugin and inherited a `PATH` where
   `latch --version` works. In Codex, check that you trusted the hooks in `/hooks`.
4. Make a Git-visible change using a supported native edit tool. The default
   `after_edit` gate skips no-op edits. File filters can also skip a check.

## A command failed to launch

Check the executable in the command shown by `latch explain`. Install that
runner or tool, then start your harness from a terminal that can find it.

## A turn-end failure is missing from the chat

Look for the harness's [turn-end feedback](/docs/hooks#where-reports-appear).
The failed report should appear once on the next prompt in the same session and
working directory.
