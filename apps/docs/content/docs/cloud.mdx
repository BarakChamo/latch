Use the same checks you use locally. The setup depends on **where the
harness process runs** and **which hooks the provider loads**. Installing
the binary is enough for manual checks. Automatic feedback also needs
the lifecycle hooks.

| Where your session runs | Start here | Latch verification |
| --- | --- | --- |
| Claude Code cloud, one repository outside Projects | [Run the Claude setup command](#single-repository-cloud-session). | Provider-documented hook path. Hosted Latch delivery unverified. |
| Claude Projects or Anthropic-hosted multi-repo sessions | [Use Remote Control or run the check directly](#claude-projects-and-multi-repository-sessions). | Repository command hooks do not load on these surfaces. |
| GitHub Copilot cloud agent | [Run the Copilot setup command](#github-copilot). | Linux fixture passed. The hosted task attempt returned 403. |
| Codex Cloud | [Run the CLI in the checkout or in CI](#codex). | Managed orchestration does not run Latch command hooks. |
| OpenHands Cloud, remote Canvas, or Enterprise | [Run the OpenHands setup command](#openhands). | Local Canvas verified. Hosted delivery unverified. |
| OpenCode, Pi, Kimi, or Grok Build on a host you control | [Install where the agent runs](#other-integrations). | Local integration verified. Managed-service delivery unverified. |

[Check local compatibility](/docs/hooks#where-reports-appear) · [Verify a hosted session](#verify-a-new-environment)

## Claude Code

### Single-repository cloud session

From your Git project, run this once with Python 3.9 or later.

```sh
curl -fsSL https://raw.githubusercontent.com/BarakChamo/latch/main/distribution/cloud/setup-hooks.py | python3 - claude
```

Commit the two files the command writes, then start a new cloud session
outside Claude Projects. Your existing settings and hooks are preserved.
The first hook downloads and verifies Latch. Use either these hooks or
the Latch plugin in local sessions to avoid running the checks twice.
[Claude cloud settings](https://code.claude.com/docs/en/settings#settings-in-cloud-sessions)

### Claude Projects and multi-repository sessions

Anthropic-hosted Project threads and multi-repo sessions skip repository
hooks. Use Remote Control with your regular Claude Code plugin, or run
the check directly in the hosted checkout or in CI.
[Claude Projects](https://code.claude.com/docs/en/projects#what-threads-pick-up-from-your-repositories)

## GitHub Copilot

From your Git project, run this once with Python 3.9 or later.

```sh
curl -fsSL https://raw.githubusercontent.com/BarakChamo/latch/main/distribution/cloud/setup-hooks.py | python3 - copilot
```

Merge the two generated files into the **default branch**, then start a
new Copilot cloud task. The first hook downloads Latch. Choose Actions
if your checks need dependency setup before the session starts.
[GitHub cloud hooks](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/use-hooks) · [Dependency setup](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/customize-the-agent-environment)

## Codex

In managed Codex Cloud, [install the CLI](#install-in-the-environment)
and run `latch run turn_end` in the checkout or in CI. For automatic
checks, [install the plugin](/docs/quickstart#codex) in a Codex CLI
session running on the machine with the checkout.
[Codex cloud hook support](https://learn.chatgpt.com/docs/hooks#hooks-with-cloud-orchestration)

## OpenHands

If you control the Canvas backend, use [Customize → Plugins](/docs/plugins#agent-canvas).
For a hosted workspace, run this once in your Git repository with Python
3.9 or later.

```sh
curl -fsSL https://raw.githubusercontent.com/BarakChamo/latch/main/distribution/cloud/setup-hooks.py | python3 - openhands
```

Commit the two generated files and open the repository root as the working
folder for a new conversation. [OpenHands repository hooks](https://docs.openhands.dev/openhands/usage/customization/hooks)

## Install in the environment

For manual checks or CI, use the [standalone installer](/docs/cli#install-the-cli)
in the environment setup and run `latch run turn_end` in the checkout.
Automatic hooks need access to GitHub release assets on first use. For
restricted networks, allow the release download or run your checks in CI.
[Standalone downloads](/docs/cli#standalone)

## Other integrations

Use the regular plugin install when the harness itself runs alongside the
checkout on a VM or container you control.

| Harness | Where to install |
| --- | --- |
| OpenCode | [Install on the OpenCode server](/docs/quickstart#opencode), even if you connect from a separate desktop app or TUI. [OpenCode plugin loading](https://opencode.ai/docs/plugins/) |
| Pi | [Install on the machine running Pi](/docs/quickstart#pi) and start Pi in the project. You can also commit the project package declaration and trust the workspace on that machine. [Pi package scope](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/packages.md) |
| Kimi Code | [Install on the host running Kimi Code](/docs/quickstart#kimi-code). Browser and Remote Control use that host. A local CLI with remote tools runs hooks beside the CLI, so use a CLI hosted with the checkout for automatic checks. [Kimi Remote Control](https://moonshotai.github.io/kimi-code/en/guides/web.html) · [Hook location](https://moonshotai.github.io/kimi-code/en/customization/hooks) |
| Grok Build | [Install into Grok Build](/docs/quickstart#grok-build) on the machine you connect to. [Remote sign-in](https://docs.x.ai/build/overview) |
| Cursor, Devin, Kiro | [Preview adapters](/docs/plugins#preview-integrations) cover local CLI setups. Use the project’s check directly or in CI on managed cloud services. |

## Verify a new environment

1. In a fresh agent session, try a read-only turn and then a real edit
   that fails a check. With defaults, the read-only turn should skip and
   the edit or changed turn should run its configured check once.
2. Confirm where the report lands, then restore the file and try a passing
   change. Passing checks are quiet by default.
   [Report timing and `continue_once`](/docs/hooks)
