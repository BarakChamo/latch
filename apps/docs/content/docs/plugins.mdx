The bundled Latch plugin includes the executable. It registers [automatic hooks](/docs/hooks) and exposes `run_turn_end` and `search_output`.
Start the harness from the directory containing your
`latch.json` or [package scripts](/docs/project-scripts).

If your coding agent runs in a hosted environment, use the
[cloud setup guide](/docs/cloud).

## Install and manage the plugin

Follow the [quickstart](/docs/quickstart) to get the bundle for macOS or
Linux. Run the command for your agent from the extracted folder.

| Harness | Install from the bundle |
| --- | --- |
| Codex | `./install codex` |
| Claude Code | `./install claude` |
| GitHub Copilot CLI | `./install copilot` |
| OpenCode | `./install opencode` |
| Pi | `./install pi` |

The installer registers Latch with your harness. OpenCode uses a local
plugin from its config directory and Pi uses its extension manager.
Keep the extracted folder so your harness can find the bundled executable.
Your project’s tools, such as npm or uv, still need to be available to the
harness.

Start a new session after installation. In Codex, open `/hooks` and review
and trust the Latch hooks. The OpenCode plugin was verified with 1.18.31,
1.19.6, and 2.3.2. Pi requires 1.5.2 or later with built-in MCP enabled.

| Harness | Find the plugin | Uninstall Latch |
| --- | --- | --- |
| Codex | `codex plugin list` | `codex plugin remove latch@latch-local` |
| Claude Code | `claude plugin list` | `claude plugin uninstall latch@latch-marketplace` |
| GitHub Copilot CLI | `copilot plugin list` | `copilot plugin uninstall latch@latch-marketplace` |
| OpenCode | Look for `latch.js` in `${XDG_CONFIG_HOME:-$HOME/.config}/opencode/plugins`. | Remove that link. |
| Pi | `pi list` | `pi remove <absolute bundle path>/plugins/pi` |

Use one installation method per project to avoid duplicate hooks.

## Additional local integrations

Use the same release bundle for the integrations below. The preview installers require the `--preview` flag.

| Harness | Setup | Feedback |
| --- | --- | --- |
| OpenHands CLI | From your project, run `/path/to/bundle/install openhands`. | Native file edits and changed turns run checks. The next prompt receives reports. |
| Kimi Code CLI | Run `./install kimi` in the bundle, paste the printed command into Kimi Code, and approve installation. | Changed turns run checks. The next prompt receives reports. |
| Cursor CLI (preview) | From your project, run `/path/to/bundle/install cursor --preview`. | The post-tool hook returns edit diagnostics. Turn-end diagnostics go to hook stderr. |
| Devin CLI (preview) | From your project, run `/path/to/bundle/install devin --preview`. | The post-tool hook returns edit diagnostics. Failed turn reports go to the next prompt. |
| Grok Build | From your project, run `/path/to/bundle/install grok`. | The post-tool hook returns edit diagnostics. Turn-end diagnostics go to hook stderr. |
| Kiro CLI V3 (preview) | From your project, run `/path/to/bundle/install kiro --preview`. | The post-tool hook returns edit diagnostics. Failed turn reports go to the next prompt. |

The preview adapters have automated hook protocol tests. Treat their
feedback as provisional until verified in a session. For Grok Build, review
the workspace hooks and trust the folder with `/hooks-trust`. Workspace installers write absolute local paths into harness
configuration. Keep those entries local. To uninstall them, remove the
hook entries whose command ends in `# latch-installed` and remove the
`latch` MCP server entry. In OpenHands, the MCP entry lives in the user
configuration. In Kimi Code, use `/plugins remove latch`.

## Run checks from chat

Ask your agent to call the Latch tool.

> Use Latch’s `run_turn_end` tool in this project and tell me which checks failed.

`run_turn_end` runs the configured `turn_end`
commands immediately in the project's working directory, even when the
worktree is unchanged. It uses the same command order and output settings
as `latch run turn_end`. Failed checks return a tool error with diagnostics.
A successful call is quiet unless `on_success` is set to `"output"`. Your
harness may ask for approval because configured commands can modify files.

In Copilot and the additional integrations above, the agent passes the absolute
project directory to the tool. Other harnesses use the session working directory. Pi exposes
it as `mcp__latch__run_turn_end`.

For a manual `after_edit` run or a preview of the resolved configuration,
use the [CLI commands](/docs/cli) in your terminal.

## Look up details from a failure

When a report includes a `Saved log` path, the agent can pass it and a
literal query such as a test name to `search_output`. Copilot also passes
the absolute project directory. With filesystem access to the cache, the
agent can search the same file directly using its normal file tools.
Both paths use the existing log without rerunning the check.
Use [the CLI](/docs/cli#retrieve-saved-output) to replay both original streams.

## Integration commands

The plugin runs these commands for you. Each hook command reads the harness's
event JSON from standard input. `latch mcp` speaks MCP over standard input and
output.

| Command | Used by |
| --- | --- |
| `latch hook codex` | Codex lifecycle hooks |
| `latch hook claude-code` | Claude Code lifecycle hooks |
| `latch hook copilot <event>` | Copilot CLI lifecycle hooks, such as `postToolUse` and `agentStop` |
| `latch hook opencode` | The OpenCode plugin forwards prompt, edit, and idle events |
| `latch hook pi` | The Pi extension forwards prompt, edit, and settlement events |
| `latch mcp` | Codex, Claude Code, OpenCode, and Pi expose both Latch tools |
| `latch install <openhands\|cursor\|devin\|grok\|kiro> [--preview]` | Writes local hook and MCP configuration for the selected harness |
| `latch hook <openhands\|kimi\|cursor\|devin\|grok\|kiro>` | Receives native lifecycle events for the selected harness |
| `latch mcp --require-project-directory` | Copilot and the additional integrations expose both tools with an explicit project directory |

See [Hooks and feedback](/docs/hooks) for what triggers automatically and where
results appear.
