## Install from GitHub

The [installation section of the Latch guide](/docs#install-a-plugin) has
the marketplace commands for Codex, Claude Code, and GitHub Copilot CLI.
Each of those plugins bundles Latch.

### OpenCode and Pi

Download and extract the [standalone archive](/docs/cli#install-the-cli).
Set `LATCH_PLUGIN_DIR` to the extracted folder and add its `bin` directory
to your shell’s `PATH`. For example, on Apple Silicon:

```sh
export LATCH_PLUGIN_DIR="$HOME/.local/share/latch/latch-0.1.0-aarch64-apple-darwin"
export PATH="$LATCH_PLUGIN_DIR/bin:$PATH"
```

For OpenCode v1, add the absolute path to
`plugins/opencode/index.js` inside `LATCH_PLUGIN_DIR` to the `plugin`
array in `opencode.json`. For OpenCode v2, add the absolute
path to the `plugins/opencode` directory to the `plugins` array instead.
Run the following to get the path to paste:

```sh
printf '%s\n' "$LATCH_PLUGIN_DIR/plugins/opencode"
```

For Pi 1.5.2 or later with MCP enabled:

```sh
pi install "$LATCH_PLUGIN_DIR/plugins/pi"
```

### Find or remove a plugin

| Harness | Find the plugin | Uninstall Latch |
| --- | --- | --- |
| Codex | `codex plugin list` | `codex plugin remove latch@latch-tools` |
| Claude Code | `claude plugin list` | `claude plugin uninstall latch@latch-tools` |
| GitHub Copilot CLI | `copilot plugin list` | `copilot plugin uninstall latch@latch-tools` |
| OpenCode | See the project's or user's OpenCode configuration. | Remove the Latch entry. |
| Pi | `pi list` | `pi remove "$LATCH_PLUGIN_DIR/plugins/pi"` |

Use one installation method per project to avoid duplicate hooks.

## Additional local integrations

From your project, use the installed `latch` command to register workspace hooks. Kimi Code uses the plugin directory from the standalone archive.

| Harness | Setup | Feedback |
| --- | --- | --- |
| OpenHands CLI | Run `latch install openhands`. | Native file edits and changed turns run checks. The next prompt receives reports. |
| Kimi Code CLI | In Kimi Code, run `/plugins install /absolute/path/to/extracted-latch/plugins/kimi` and approve installation. | Changed turns run checks. The next prompt receives reports. |
| Cursor CLI (preview) | Run `latch install cursor --preview`. | The post-tool hook returns edit diagnostics. Turn-end diagnostics go to hook stderr. |
| Devin CLI (preview) | Run `latch install devin --preview`. | The post-tool hook returns edit diagnostics. Failed turn reports go to the next prompt. |
| Grok Build | Run `latch install grok`. | The post-tool hook returns edit diagnostics. Turn-end diagnostics go to hook stderr. |
| Kiro CLI V3 (preview) | Run `latch install kiro --preview`. | The post-tool hook returns edit diagnostics. Failed turn reports go to the next prompt. |

The preview adapters have automated hook protocol tests. Treat their
feedback as provisional until verified in a session. For Grok Build, review
the workspace hooks and trust the folder with `/hooks-trust`. Workspace installers write absolute local paths into harness
configuration. Keep those entries local. To uninstall them, remove the
hook entries whose command ends in `# latch-installed` and remove the
`latch` MCP server entry. In OpenHands, the MCP entry lives in the user
configuration. In Kimi Code, use `/plugins remove latch`.

## Run checks from chat

Ask your agent to call the Latch tool.

> Use Latch’s `run_turn_end` tool in this project and tell me which checks failed.

`run_turn_end` runs the configured `turn_end`
commands immediately in the project's working directory, even when the
worktree is unchanged. It uses the same command order and output settings
as `latch run turn_end`. Failed checks return a tool error with diagnostics.
A successful call is quiet unless `on_success` is set to `"output"`. Your
harness may ask for approval because configured commands can modify files.

In Codex, Copilot and the additional integrations above, the agent passes the absolute
project directory to the tool. Other harnesses use the session working directory. Pi exposes
it as `mcp__latch__run_turn_end`.

For a manual `after_edit` run or a preview of the resolved configuration,
use the [CLI commands](/docs/cli) in your terminal.

## Look up details from a failure

When a report includes a `Saved log` path, the agent can pass it and a
literal query such as a test name to `search_output`. Copilot also passes
the absolute project directory. With filesystem access to the cache, the
agent can search the same file directly using its normal file tools.
Both paths use the existing log without rerunning the check.
Use [the CLI](/docs/cli#retrieve-saved-output) to replay both original streams.

## Integration commands

The plugin runs these commands for you. Each hook command reads the harness's
event JSON from standard input. `latch mcp` speaks MCP over standard input and
output.

| Command | Used by |
| --- | --- |
| `latch hook codex` | Codex lifecycle hooks |
| `latch hook claude-code` | Claude Code lifecycle hooks |
| `latch hook copilot <event>` | Copilot CLI lifecycle hooks, such as `postToolUse` and `agentStop` |
| `latch hook opencode` | The OpenCode plugin forwards prompt, edit, and idle events |
| `latch hook pi` | The Pi extension forwards prompt, edit, and settlement events |
| `latch mcp` | Claude Code, OpenCode, and Pi expose both Latch tools |
| `latch install <openhands\|cursor\|devin\|grok\|kiro> [--preview]` | Writes local hook and MCP configuration for the selected harness |
| `latch hook <openhands\|kimi\|cursor\|devin\|grok\|kiro>` | Receives native lifecycle events for the selected harness |
| `latch mcp --require-project-directory` | Codex, Copilot, and the additional integrations expose both tools with an explicit project directory |

See [Hooks and feedback](/docs/hooks) for what triggers automatically and where
results appear.
