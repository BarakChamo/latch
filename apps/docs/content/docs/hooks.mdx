description: Understand what triggers a check and where each harness shows its result.

Follow the [quickstart](/docs#2-enable-your-harness-plugin) to install the plugin
for your harness.

## When checks run

| Event | Trigger | Default comparison |
| --- | --- | --- |
| `after_edit` | A native edit tool finishes. | Immediately before and after that edit. |
| `turn_end` | The agent finishes a turn. | The start and end of the turn, including changes made through shell commands. |

A pre-existing dirty file triggers a check only if it changes again during
the comparison window. Latch checks Git-visible files and runs the commands
when a reliable comparison is unavailable.

| Harness | Native edit tools |
| --- | --- |
| Codex | `apply_patch` |
| Claude Code | `Edit`, `Write`, `MultiEdit`, `NotebookEdit` |
| GitHub Copilot CLI | `create`, `edit`, `str_replace_editor`, `apply_patch` |

## Where reports appear

Edit reports are attached to the tool result in the same turn. Turn-end reports
use the harness's hook feedback. Failed turn-end reports also appear once at
the next prompt in the same session and working directory.

| Harness | Turn-end feedback |
| --- | --- |
| Codex | App-server hook warning. The tested `codex exec --json` output omits it. |
| Claude Code | Informational hook event. |
| GitHub Copilot CLI | Hook warning. |

A failed check finishes with the current turn. Latch never starts a repair pass.
